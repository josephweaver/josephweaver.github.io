# Epistemic Control Note #1

## It Was 95°F Today, So Naturally I Wrote Code

Well folks, today it was over **95°F**, so I did the only sensible thing: I stayed inside and coded all day with a little help from AI.

I've been working on **GORC — Governed Orchestration for Research Computing** for the past couple of weeks. (Well... years, if I'm being honest.) Along the way I've also been developing what I call an **Epistemic Control** model for AI-assisted software development: a process that keeps the human in control while still taking advantage of what modern language models do well.

Today I had two small revelations that ended up making a surprisingly large difference.

## Revelation #1: Let AI Design the Epic

Instead of asking the AI to immediately start coding, I began asking it to design an epic first.

My prompt looked something like this:

> "I want to rework the variable resolution component in the controller startup path such that it:
>
> 1. ...
> 2. ...
> 3. ...
>
> Please create `docs/epics/var-res-ctl-start/README.md` describing the design. Also include any open questions or ambiguities."

The magic wasn't the initial document.

The magic came afterwards.

I simply said:

> "Let's go through the open questions one by one and refine the design."

This produced an exceptionally solid design document. More importantly, it exposed assumptions and ambiguities before a single line of code was written.

Once the design was complete, I could switch from an expensive reasoning model to a much smaller model for implementation. Since each feature was already well specified, the coding tasks required far less context.

The result?

**Roughly a 10× reduction in token usage during implementation.**

Large models are fantastic architects. Small models are often perfectly capable builders.

## Revelation #2: Move the Parentheses

This one sounds almost ridiculous.

I changed my workflow from:

> **Epic → (All Features) → (All Implementation)**

to

> **Epic → (Feature + Implementation) → (Feature + Implementation) → ...**

At first glance it looks like I merely moved some parentheses.

But it fundamentally changed how I collaborated with the AI.

The traditional workflow looks like this:

1. Design the entire epic.
2. Break it into every feature.
3. Finish all design work.
4. Finally start implementing.

Instead, I now do this:

1. Design the overall epic.
2. Fully design **one** feature.
3. Implement that feature immediately.
4. Learn from the implementation.
5. Apply those lessons when designing the next feature.

The feedback loop becomes:

> Human → AI → Code → Human → AI → Code → ...

instead of,

> Human → AI → ... →  Human → AI → Code → ... → Code

The implementation continuously validates the design. Every completed feature teaches me something that improves the next feature.

I found that my understanding "bounced" between myself and the AI much more effectively. Rather than accumulating uncertainty over an entire epic, uncertainty gets resolved one feature at a time.

## The Structure

I've settled on a simple folder structure:

```text
epic-name/
├── README.md          # Goals, design, architecture, open questions
├── 001-feature-name.md
├── 002-feature-name.md
├── 003-feature-name.md
└── ...
```

The `README.md` captures the vision for the entire epic, while each numbered feature is a small, independently implementable slice. Once a feature is agreed upon, implementation begins immediately.

## Closing Thoughts

One thing that has become increasingly clear to me is that AI isn't replacing software design—it is changing where the design effort pays off.

A well-designed feature dramatically reduces the amount of reasoning required during implementation. That means cheaper models become surprisingly capable, context windows stay small, and I retain a much stronger understanding of the code being written.

For me, that's what Epistemic Control is really about: not writing code faster, but structuring the conversation so that both the human and the AI remain aligned throughout the development process.

Today's discoveries felt like another step in that direction.
